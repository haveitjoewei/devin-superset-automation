Devin is the coding worker. My service owns orchestration, job state, and verification — deliberately simple: Postgres, not Kafka; a custom handler, not a black-box integration.

03 · What I built

The components — Devin codes, my service orchestrates.

Devin (green) is the only autonomous-coding component. Everything else — validation, state, verification, reporting — is orchestration I own, so it stays inspectable, costed, and governed. Adapters are pluggable: a new trigger or reporter is one file.

05 · Measurement

Verified outcomes, not AI activity.

Merge is a human step, so I don't hide it inside one MTTR number. Three metrics separate what the system controls from the org's review bottleneck.
