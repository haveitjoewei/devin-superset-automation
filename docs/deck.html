02 · Architecture

Devin makes the fix. A person approves it.

Before

An engineer does the repair
An update bot proposes a change
Automated checks fail
An engineer investigates and fixes it
The team tests, reviews, and merges
→

After

Devin does the repair
A scan finds a blocked update
A person approves the work
Devin fixes the code and tests
Slack and GitHub show progress
A person reviews and merges
DETECT→APPROVE→FIX→CHECK→MERGE

The app starts Devin, tracks progress, and posts updates. Failed checks get one repair attempt before a person takes over.

03 · What I built

How the services connect.

Devin writes the fix. The app connects the services and records what happened. People approve the work and the merge.

04 · Why Devin

Devin handles the coding work.

ApproachWork required
Fixed scriptsGood for predictable changes. New failure patterns need new repair logic.
Build your own coding agentBuild and maintain the coding environment, agent, and integrations.
This Devin integrationDevin investigates and edits the code. This app starts the work, follows progress, and reports results.

The integration uses Devin’s API to start sessions, check progress, and request a repair after failed checks.

05 · Measurement

Measure useful fixes.

For a pilot, track how quickly fixes are ready, how long review takes, and how much help they need.

Reliability
Fixes without manual edits

These are proposed pilot measures. The original dashboard screenshots include sample data and simulated results. Current live metrics exclude them and report ACUs, not dollar savings.
